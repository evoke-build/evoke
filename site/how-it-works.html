How a sentence you type becomes a program call.

A reflex is a small program you install and ask for in your words. This page follows one natural-language command to the program it runs. A classifier reads the sentence, and a bar set by what the program changes decides whether it runs, asks you first, or stops.

A reflex

01

A reflex brings its program and the words to ask for it.

A reflex is a program with a manifest, reflex.toml, beside it. The manifest states what the program does, what it is not for, which inputs it takes, and how careful to be. The classifier reads these words. The program receives the values of its inputs.

contact/reflex.tomlby the author
reflex = 1

description = """
Look up a person's email address in the team directory.
One person at a time; prints the address."""

not_for = ["writing to anyone", "phone numbers", "adding a person to the directory"]
tags    = ["people"]
effect  = "read"
confirm = "Look up {name}'s address?"
run     = "contact.mts"

[args.name]
ask   = "Whose address?"
vocab = "people"

[yields]
email = "email"

[examples]
"look up dana's address"    = {}
"what is sam's email"       = {}
"find the address for dana" = {}
description · not_for
What it is for, and what it is not. A plain description, and the near misses it must turn down.
effect
How careful to be. The author declares read, write or destructive. A read needs less certainty to run than a write, and a destructive one always asks. You can make it stricter, never looser.
confirm
Its own question. The line you answer when evoke wants your yes first.
run
The program that runs. A file its author wrote, or a command you already use. Your sentence fills its inputs and never changes what runs.
[args.name]
The input it takes. A word from people, a list you keep. Every input has one source: options the author listed, a word list you keep, a piece of what you typed, or a yes/no switch.
[yields]
What its result holds. An email address. A later step in the same sentence that needs one can take it.
[examples]
Sentences that show it in use. The classifier reads these too, with the description and the near misses.
See both manifests in the contact example →

Your sentence

02

Your sentence picks the reflex and fills its inputs.

The classifier is Jev, TypeSafe AI's model. evoke turns every installed manifest into closed questions and sends them all in one request. A sentence with «and» or «then» can make a few more. Jev answers each question with a probability, and evoke accepts only an answer from the choices it offered.

  1. 01Which reflex?One choice over every installed reflex, or none of them. Built from each description, its near misses and its examples.
  2. 02Does it fit?A yes or no for each reflex. When a second reflex fits well too, the sentence may ask for two things, so evoke asks you before anything runs.
  3. 03Which value?One choice per input: an option the author listed, a word from a list you keep, or a piece of your sentence taken word for word. Or «unstated».
evoke try
$ evoke try "kill the lights in the den"
  lights 0.91 · none 0.06 · timer 0.02 · volume 0.01
  room   den 0.85 · unstated 0.10 · office 0.05
  state  off 0.88 · on 0.05 · dim 0.05 · unstated 0.02
  fits   lights 0.70 · timer 0.05 · volume 0.05
  run · weakest: room 0.85
a missing value
$ evoke "kill the lights"
  Which room?  [1] den  [2] office  [+] add one  > 1
  lights room="den" state="off" · write · weakest: state 0.58
  Set the den lights off?  [y]es [n]o [t]each > t
+ overlays/lights.toml  [examples] "kill the lights" = { state = "off" }
den lights off
  1. 1«den» matched a word of yours. Rooms are a word list you keep, called a vocabulary. The classifier reads each word's meaning, and the program gets its value.
  2. 2«kill» meant off at 0.88. Off is an option the author listed. Without «in the den», the room was unstated, so evoke asked for it.
  3. 3Then evoke asked for a yes. Off got only 0.58 this time, under the bar for a write. Typing t answered yes and saved the phrase in a file of yours.
  4. 4Some things are never read from a sentence. A setting like a bridge address, or a secret, is set once with evoke config.

The gate

03

How sure evoke must be depends on what the program changes.

evoke guarantees that every value is one the reflex allows. It cannot guarantee that it read you right. That is why a bar, set by what the program changes, decides what runs without a question.

  1. RunAt or over the bar, with every required input stated. It runs on the classifier's reading, without a question. The call prints with its confidence, then the result.
  2. AskA required input was not stated, or a value fell outside its range. evoke asks the input's own question, then checks the bar again with your answer.
  3. Confirmevoke shows the call and waits for your yes: under the bar, when a second reflex fits well too, or when something you typed went unused. A destructive reflex always waits.
  4. StopNothing fits, and evoke abstains: the ranking prints and nothing runs. In a sentence of several steps, one part that fits nothing stops the whole sentence.

What a number means. The classifier's provider trains its probabilities to be calibrated: across many answers, those given 0.85 should be right about 85 times in 100. evoke shows every one, and evoke test checks your own sentences. You can read and change the bars in a file you own.

A handoff

04

One step's result can fill the next step's input.

One sentence can ask for several reflexes, and evoke shows the numbered plan before anything runs. When your words point back to an earlier step, and its result holds the kind of value a later step lacks, that value passes along.

evoke
$ evoke "look up dana's address and email them"
  1  contact name="dana"  0.90
  2  mail · takes email from 1
dana <dana@example.com>
  2  mail to="dana@example.com"  0.88
drafted to dana@example.com
  1. 1The plan comes first. Two numbered lines show each step, and what step 2 takes from step 1. A required input is filled with the value. An optional one is decided again, the value written into that step's words.
  2. 2No field is guessed. When two fields could fit, evoke stops and names them. When a step points back but takes nothing, evoke asks before anything runs. When a part matches nothing, evoke refuses the whole sentence.

A result passes to a later step only when all of this holds.

  • The earlier reflex declares a field of its result under [yields], with its kind: a number, a duration, an email address, a URL, a quoted phrase, or a list of records made of these.
  • Its program returns that field with its result.
  • The later step has an input of the same kind, read from your sentence, that your sentence left empty. An input filled from the author's options or from a word list never takes a result.
  • Your words point back to the earlier step, with a word like «it», «them» or «the address».
  • Exactly one field fits, or your words name the one you mean.

contact and this mail are stand-ins from evoke's tests, and so are the numbers. The collection's mail opens a draft in your mail app, and nothing is sent. No reflex in the collection declares [yields] yet: to pass a result today, write a reflex that does.

A continuation

05

A program can name the next step.

A reflex's program can return the next sentence with its result. A short loop in your application, written with the TypeScript SDK, submits it as if you had typed it. This is the runbook pattern, a second way to chain, where each program decides what follows.

~/runbook
$ node runbook.ts "drain the primary"
primary drained
Promote the replica now?  [y]es [n]o > y
replica promoted
writes landing on the new primary
  1. 1Two ways to chain. In one sentence of several steps, evoke plans the steps and passes declared results. In a continuation, each program names the next step, and your loop submits it.
  2. 2The database programs are stand-ins. They print fixed lines. Yours would drain, promote and check a real database.

Your words

06

Your names and phrases stay in your files.

A vocabulary is a word list you keep, like rooms or people, and each word has a meaning the classifier reads. An overlay holds your phrases for one reflex. Both sit on top of the shipped manifest, and an update keeps them.

evoke show
$ evoke show lights
  description = "Turn the lights in one room on, off, or dim them.\nCeiling and lamp lights only."
  …
  [args.state]
+ ask = "On, off or dim?"
  options.on = "Switch on."
  …
  [examples]
  "turn on the kitchen lights" = { state = "on" }
+ "kill the lights" = { state = "off" }
  1. 1A + marks a line of yours. Teach one with evoke teach, or answer t when evoke asks for a yes. You can also edit the file by hand.
  2. 2An update never overwrites your files. It lists what changed, takes the author's new wording where you had none, and keeps yours where you had some.

The lights reflex here comes from evoke's tests. You cannot install it.

Your application

07

What stays yours to decide.

evoke decides which call a sentence means, and whether it may run without a question. Four things stay with you and your application.

  • Who may ask for what.A decision is plain data your code holds before anything runs. Check the person, the account or the time of day first. The approval example waits for a second person.
  • What the programs do.A reflex runs with your permissions, and there is no sandbox yet. Read what you install. Its effect is the author's claim, and you can make it stricter, never looser.
  • What happens after a partial run.A step that fails stops the steps after it. evoke undoes nothing that already ran, and your application decides what happens next.
  • Where your sentence and key go.Each decision is one request to the classifier, with your own key, billed by its provider. At the terminal, a sentence you repeat is answered from a local cache. Nothing goes to evoke.build.

Questions

Requests, running by name, and changing the bars.

How many requests does one sentence make?

A sentence that asks for one thing is one request, carrying every question at once. When it has a word like «and» or «then», one request first asks whether each such word joins two steps. With three steps or more, another may ask which step a word like «them» points to. Then each step is one request, and a step decided again with a value from an earlier step makes one more.

At the terminal, a sentence you repeat, with the same reflexes installed, is answered from a local cache without a request.

Can I run a reflex without the classifier?

Yes. evoke run takes a call you write yourself, like evoke run power action=restart, and asks no classifier. Every value is still checked, so a word missing from your list or a number out of range is refused. A destructive reflex still asks for your yes.

Running by name, in the manual →

Can I change the bars?

Yes. The defaults are 0.5 to pick a reflex at all, 0.6 for a reflex that only reads, and 0.8 for one that writes. You can raise or lower them for your machine in evoke.toml. A read's bar can never be higher than a write's, and nothing lets a destructive reflex run without your yes.
