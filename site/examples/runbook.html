A runbook where each step names the next. Only the destructive one waits for a yes.

A runbook that waits for a yes before the step you cannot undo. A reflex is a small program you install and ask for in your words. Here each step is a reflex: drain, fail over, check. Each step's program names the next step in words, and a loop of six lines in your app passes that sentence to evoke. The database programs shown are stand-ins that return fixed lines.

The request and the result

01

Three steps run from one typed sentence.

The person types the first step. The drain's program names the failover, and the failover names the check. Recorded on 21 September 2026 against Jev, TypeSafe AI's model, which reads each sentence.

~/runbookdrainfailoververify
$ node runbook.ts "drain the primary" primary drained Promote the replica now? [y]es [n]o > y replica promoted writes landing on the new primary
  1. 1A step names the next. The program returns data.next, a sentence. The loop passes it to evoke as if a person had typed it.
  2. 2Every step is decided on its own. The drain changes something, so it runs without a question only at 0.8 or more. The check only reads, so 0.6 is enough.
  3. 3Only the failover asks. It cannot be undone, so its author marked it destructive. It asks every time, however sure evoke is.

runbook.tsyours
// The same runbook, in code. Three reflexes, one loop.
import { load, reflex } from "@evoke-build/evoke"
import { jev } from "@evoke-build/evoke/jev"
import { done, handlers } from "../terminal.ts"

const drain = reflex({
  description: "Drain traffic from the primary database.\n" +
    "New connections go to the replica; open ones finish.",
  effect: "write",
  confirm: "Drain the primary?",
  examples: { "drain the primary": {} },
}, async () => ({
  text: "primary drained",
  data: { next: "fail over to the replica" },
}))

const failover = reflex({
  description: "Promote the replica to primary.\n" +
    "The old primary is demoted; it cannot be undone from here.",
  effect: "destructive",
  confirm: "Promote the replica now?",
  examples: { "fail over to the replica": {} },
}, async () => ({
  text: "replica promoted",
  data: { next: "check that writes land on the new primary" },
}))

const verify = reflex({
  description: "Check that writes land on the current primary.",
  effect: "read",
  confirm: "Check writes?",
  examples: { "check that writes land on the new primary": {} },
}, async () => "writes landing on the new primary")

const reflexes = { drain, failover, verify }
const runbook = await load({ reflexes, adapter: jev() })

let next: string | undefined = process.argv[2]
while (next) {
  const step = await runbook.handle(next, handlers)
  if (step.outcome !== "ran") break
  console.log(step.result.text)
  next = (step.result.data as { next?: string } | undefined)?.next
}
done()

terminal.tsthe two handlers
// The two handlers the ops and runbook apps share.
// A confirm is a question; an ask is a numbered menu, or a blank to type into.
import { createInterface } from "node:readline/promises"
import type { Handlers } from "@evoke-build/evoke"

const { stdin: input, stdout: output } = process
const terminal = createInterface({ input, output })

// Fits a project of any reflexes
export const handlers: Handlers<any> = {
  confirm: async d => {
    const typed = await terminal.question(`${d.prompt.template}  [y]es [n]o > `)
    return typed.startsWith("y")
  },
  ask: async d => {
    const given: Record<string, string> = {}
    for (const { arg, ask, choices } of d.missing) {
      const keys = choices.type === "options" ? Object.keys(choices.options)
        : choices.type === "vocab" ? Object.keys(choices.words) : []
      const menu = keys.map((key, i) => `[${i + 1}] ${key}`).join("  ")
      const typed = await terminal.question(`${ask}  ${menu}${menu && "  "}> `)
      given[arg] = keys[Number(typed) - 1] ?? typed
    }
    return given
  },
}

export const done = () => terminal.close()
  1. 1The programs are stand-ins. Each returns its line and the next sentence. Yours would drain, promote and check a real database.
  2. 2The loop stops when a step does not run. A no, a sentence that fits no reflex, or a program that fails ends it. Nothing after it runs, and nothing before it is undone.
  3. 3The same loop over files or code. load() takes a directory with its evoke.toml, or the reflexes handed over as objects.

One boundary

03

The destructive step waits for a yes.

The failover cannot be undone from where it runs, so its author marked it destructive. Answer no, and the loop ends there. The drain stays done, and the check never runs.

node
$ node runbook.ts "drain the primary"
primary drained
Promote the replica now?  [y]es [n]o > n

The question is the one the failover's author wrote. Answer no, and the handler returns false. handle() then returns declined, and the loop stops at its break. handle(), in the manual →

Set it up

04

Run the runbook from one file, with the SDK.

runbook.ts holds the three reflexes and the loop, so it runs on its own. Its programs are stand-ins that change nothing, so it is safe to run.

  • Node 24.5 or newer, and the SDKThe loop runs in your app.
  • A classifier keyGet a key from TypeSafe AI. Each step is one request, billed to your key.
  • Real programsThe three shown return fixed lines. Yours would call your database, and pass the signal it receives to every call: each decision has 30 seconds.
  • Recovery, decided by youA step that fails stops the rest. What to do about the steps already done is your application's call.
  • A chat botevoke has no chat integration. In an app, the confirm handler is where a bot would ask for its yes.

  1. Make the project

    A folder for the app, with a package of ES modules and the SDK.

    mkdir -p ~/runbook && cd ~/runbook && npm init -y && npm pkg set type=module
    npm install @evoke-build/evoke

  2. Save the two files

    Save runbook.ts from the code tab above in ~/runbook. Save terminal.ts from the app tab in your home folder, the folder above it, where runbook.ts imports it from.

  3. Start the runbook

    The drain runs, then the failover asks for its yes. Answer y, and the check runs. Answer n, and the loop stops there.

    export TYPESAFE_API_KEY=<value>
    node runbook.ts "drain the primary"

To make it yours, replace each stand-in with a program that calls your database. Keep data.next, which names the step that follows.
