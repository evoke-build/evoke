You invoke
a function. You evoke
a reflex.

A reflex is a small program you install and ask for in your words. Type a natural-language command, and evoke runs the reflex that matches, or asks you first. One sentence can ask for several.

Get started

evoke is free and open source. A classifier reads each sentence over the network, and its provider bills your own API key. Nothing you type goes to evoke.build.

A reflex

01

Install a reflex, and you can ask for it. Two that fit can pass a result along.

The mail reflex, from the collection, is a small program and its manifest. The manifest says what it does, what it is not for, and what to ask you when something is missing.

mail/reflex.tomlby the author
reflex = 1

description = """
Start an email in your mail app.
To one address, with an optional subject; nothing goes out until you press send."""

not_for = ["reading or searching mail", "chat and text messages"]
effect  = "write"
confirm = "Write to {to}?"
run     = "mail.mts"

[args.to]
ask  = "To which address?"
pick = "email"

[args.subject]
ask      = "What is the subject?"
pick     = "quoted"
optional = true

[examples]
"email ana@example.com"                   = { to = "ana@example.com" }
'write to sam@example.com about "friday"' = { to = "sam@example.com", subject = "friday" }
description
What it does, in plain words. The classifier reads this to pick the reflex you mean.
not_for
What it does not do. Naming the near misses keeps a similar request from landing here.
effect
How careful to be. Its author declares read, write or destructive. A write runs on its own when evoke is sure enough. A destructive one always asks.
confirm
Its own question. The line you answer when evoke asks before it runs.
[args.to] · [args.subject]
What it needs from you. An email address, taken from your sentence word for word. The subject is optional.
[examples]
Sentences that teach. You can add your own, and they stay in a file of yours.

Two fit when one returns a kind of value and the other takes it. The walkthrough's contact declares [yields] email = "email", so its address can fill to. No collection reflex declares a result yet.

Decisions

02

It runs when it is sure enough. It asks when it is not, or when a change cannot be undone.

A wrong reading is possible. A made-up value is not. So each reflex has a bar: how sure evoke must be before it runs without asking.

ran
$ evoke "set the volume to 40 percent"
  volume level="40 percent"  0.93
volume 40%

Sure enough, so it ran. The number is how sure evoke is, going by its least sure answer. Changing the volume needs 0.8.

asked
$ evoke "kill the wifi"
  wifi state="off" · write · weakest: state 0.72
  Turn Wi-Fi off?  [y]es [n]o [t]each > t
+ overlays/wifi.toml  [examples] "kill the wifi" = { state = "off" }
wi-fi off

Under the bar, so it asked first. evoke was 0.72 sure, and a change needs 0.8. Typing t answered yes and saved your phrase in a file of yours.

declined
$ evoke "restart the computer"
  power action="restart" · destructive · weakest: route 0.97
  Really restart now?  [y]es [n]o [t]each > n
[2]

Destructive, so it asked, even at 0.97. No flag skips this question. You typed n, so nothing ran, and [2] means declined.

A reflex that only reads runs on its own at 0.6 or more, one that changes something at 0.8, and one that cannot be undone always asks. You can change these bars in a file you own.

The classifier is Jev, TypeSafe AI's model. Its provider trains each probability to be calibrated: across many answers, those given 0.85 should be right about 85 times in 100.

These sessions are what evoke printed in its tests, over answers written for them, so your own numbers will differ. evoke try shows every judgment and runs nothing.

Your own

04

Turn a command or script you already have into a reflex.

A manifest describes it, and evoke runs it when you ask. Share it with a git tag, and anyone can install it and ask for it in their own words.

scale/reflex.tomla command you have
reflex = 1

description = """
Scale a service to a number of replicas.
One deployment in one environment; the number is set, never added to."""
…
effect  = "write"
confirm = "Scale {service} in {env} to {replicas}?"
run     = [
  "kubectl", "-n", "{env}", "scale", "deployment", "{service}",
  "--replicas", "{replicas}",
]

[args.service]
ask   = "Which service?"
vocab = "services"

[args.env]
ask   = "Which environment?"
vocab = "envs"

[args.replicas]
ask   = "How many replicas?"
pick  = "number"
range = [1, 20]

[examples]
"scale checkout to 6 in staging"   = { replicas = "6" }
"run 3 replicas of search in prod" = { replicas = "3" }
…

A kubectl command becomes a reflex, with no code. run names the program and where each value goes. confirm is the question you answer when evoke asks first.

  • Any program on your PATH works, a script of yours as well as kubectl. evoke runs it directly, never through a shell, and needs no Node to do it.
  • Values arrive checked. A service must be a word from your list, and the replicas a number from 1 to 20. Out of range, evoke asks for another.
  • Or write the program yourself. evoke new hello writes a reflex that already works, and evoke check names any line to fix.

Your words

05

Teach evoke your names and the phrases you use.

«dana», in the sentence at the top of this page, came from your list of people. Your names and phrases live in files you own, and an update never touches them.

vocab/people.tomlyour word list
dana = "Dana Ortiz, operations."
sam  = "Sam Lee, sales."
evoke
$ evoke vocab places add desktop "The desktop." --value "~/Desktop"
+ vocab/places.toml  desktop = { what = "The desktop.", value = "~/Desktop" }
$ evoke teach "go dark" wifi state=off
+ overlays/wifi.toml  [examples] "go dark" = { state = "off" }
  1. 1A word list holds your names. desktop is a word you chose. The classifier reads its meaning, and the program receives its value, a folder's path.
  2. 2Teaching adds your phrase to a file of yours. Type t when evoke asks you to confirm, or use evoke teach. Every later decision reads it.
  3. 3The author's wording stays as shipped. overlays/wifi.toml is your own file for the wifi reflex's wording. An update never rewrites it.

Start

06

Start in your terminal or in your app.

On a Mac, the collection gives you thirteen reflexes to ask for. On Linux, start with a command you already run.

In your terminal

You need an API key from TypeSafe AI, and git to add the collection. Its thirteen reflexes are for a Mac, and eleven of them need Node 24 or newer.

export TYPESAFE_API_KEY=<value>
curl -fsSL https://evoke.build/install.sh | sh
evoke add evoke-build/reflexes
evoke "set the volume to 40 percent"

It prints the reflex it chose, the value it read and how sure it is, then the reflex's own line: volume 40%.

In your app

The same decisions, inside a Node application.

npm install @evoke-build/evoke

The SDK's first release on npm is on its way. Until then, the terminal route runs today. The SDK manual starts with one file, one reflex and one decision.
